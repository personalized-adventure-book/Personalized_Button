# Personalized_Product

> ⚠️ **Status: Under active development.** Features and APIs may change.

**Personalized_Product** turns a simple **natural-language message into a fully functional, personalized website** — no coding required.

The vision is for **anyone, even people who know nothing about computers**, to describe what they want in plain words (for example: *"I want a personalized children's adventure book website in French and English"*) and instantly get a complete, ready-to-use website for that product.

Despite its origins as a button-based product, the engine is fully **generic**: a single, flexible website platform that can render many different personalized product websites (books, gifts, prints, cards — anything), in multiple languages, with dynamic content, and increasingly driven by an **LLM** that generates and adapts the content from a prompt.

In short: **prompt → website.**

## Live Examples

The same engine serves multiple products. Only the `id` in the URL changes:

- https://personalized-adventure-book.github.io/Personalized_Product/?id=BK3
- https://personalized-adventure-book.github.io/Personalized_Product/?id=BT2

Each `id` corresponds to a different personalized product configuration (content, texts, images, language, features, etc.).

## What This Project Does

- Turns a **natural-language description** into a full personalized product website (the long-term, LLM-driven goal — see *LLM Integration* below).
- Hosts **multiple product websites** in one single app.
- Loads **product-specific content dynamically** based on URL parameters.
- Supports **multiple languages**.
- Uses **structured content (JSON, configs, assets)** to drive the UI.
- Keeps a **generic UI and logic**, reusable for any personalized product.

One codebase, many products, many languages, many websites — built so non-technical users never have to touch code.

## Core Idea

1. A user describes the product they want in plain language.
2. The content/configuration for that product is created (today via config files; soon generated by an LLM).
3. The product is given a unique `id` and opened via a URL like `?id=BK3`.
4. The app detects the `id` and loads the matching content/configuration.
5. The same UI engine renders a **different, fully functional product website** — language, texts, images, and features adapt automatically.

## Project Structure (Simplified)

- `app/`, `components/`, `contexts/`, `hooks/`, `utils/` — core application logic and UI components.
- `content/`, `JSONS/`, `public/` — product content, assets, and configuration.
- `types/` — TypeScript types for structured data.
- `scripts/`, `test-*.js` — debugging, testing, and utility scripts.
- `next.config*.js`, `tsconfig.json`, `tailwind.config.js` — framework and build configuration.

## How to Run Locally

1. Install dependencies:

   ```bash
   npm install
   ```

2. Start the dev server:

   ```bash
   npm run dev
   ```

3. Open in your browser:

   ```
   http://localhost:3000/?id=BK3
   ```

   Change the `id` to test different products.

## Adding a New Product

1. Create a new content/config entry for your product (JSON or config files).
2. Give it a unique `id` (for example: `MY1`).
3. Add the assets (images, texts, etc.).
4. Open `?id=MY1`.
5. The same app renders your new personalized product website — no new frontend project needed.

## LLM Integration (In Progress)

This is the heart of the project's vision: making website creation accessible to people with **zero technical background**. The goal is to let a user describe a product in a single natural-language message and have an LLM generate:

- Text content
- Structure
- Translations
- Sections and layout data

This generated content is fed into the same engine to instantly create a new, fully functional product website — a **prompt → website** pipeline for personalized products.
